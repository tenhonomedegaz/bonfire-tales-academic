# Publicação controlada de pacotes de conteúdo

`GET /admin/content-maintenance/<package_id>/` faz a prévia: confere o manifesto e o artefato instalados no servidor, a revisão de base, a revisão alvo, seus vínculos, a configuração de ativação e a disponibilidade do backup (`can_apply`). `POST` no mesmo endereço instala apenas o pacote revisado escolhido da allowlist do código. O cliente envia somente o ID da URL e `{"action":"apply","expected_base_checksum":"<checksum da base no manifesto>"}`. Não há upload, SQL, comando, caminho ou credencial variável no pedido. Os tokens e a resposta não contêm dados de jogadores.

## Configuração do servidor

- Configure **dois tokens distintos** de pelo menos 40 caracteres: `CONTENT_MAINTENANCE_READ_TOKEN` e `CONTENT_MAINTENANCE_APPLY_TOKEN`. Os arquivos locais ignorados pelo Git `scratch/content_maintenance_read_token.txt` e `scratch/content_maintenance_apply_token.txt` contêm os valores gerados para esta instalação. Transfira-os por canal seguro; nunca os envie em mensagens, URL ou Git. Token ausente ou igual ao outro desativa o respectivo acesso. Leitura não autoriza aplicação.
- Configure `CONTENT_MAINTENANCE_BACKUP_DIR` para pasta absoluta já existente, fora da árvore do projeto e da área servida pela web, com acesso restrito à conta do serviço. Configure `CONTENT_MAINTENANCE_PG_DUMP` e `CONTENT_MAINTENANCE_PG_RESTORE` se os executáveis não estiverem no PATH. A aplicação gera um dump PostgreSQL completo em formato customizado e confere seu índice antes de escrever; mantém o arquivo para recuperação.
- O serviço exige HTTPS em produção e PostgreSQL local no schema `public`, fora de recuperação. Atrás de proxy TLS confiável, ajuste `DJANGO_USE_X_FORWARDED_PROTO=true` e assegure que o proxy controla esse cabeçalho. Restrinja acesso à rota na borda sempre que possível. As credenciais normais do PostgreSQL permanecem no servidor; não são aceitas pela API.
- A auditoria `content_maintenance_audit.jsonl` fica na pasta de backup. Ela registra início, backup verificado, rollback e instalação por ID de operação, sem token, SQL ou dados pessoais. Falha de auditoria antes da escrita bloqueia a aplicação. Um lock advisory global impede aplicações simultâneas. O replay de pacote íntegro retorna `already_installed` sem escrever nem criar novo backup.
