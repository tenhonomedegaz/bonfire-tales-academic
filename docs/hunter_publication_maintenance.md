# Publicação da revisão Markdown do Caçador no PostgreSQL do servidor

A rota `POST /admin/server-logs/hunter-publication-maintenance/` executa **somente** o SQL versionado `ref/backups/hunter_markdown_publicacao_db_20260930.sql`, identificado pelo SHA-256 `9d5ab77ac02a4cb2f0310663223bf0898bec2c3f43a9eff0f3b863bfd5b341bf`. Não aceita SQL, nomes de tabelas, PKs ou conteúdo enviados pelo cliente. A rota `GET` devolve somente presença das revisões, quantidade de vínculos e se o checksum-alvo está configurado. Ambas exigem HTTPS e token Bearer de 40 ou mais caracteres; token ausente desativa a rota. O banco precisa ser PostgreSQL local, no schema `public`, fora de recuperação.

No servidor, depois de atualizar o código, configurar `HUNTER_MAINTENANCE_TOKEN` com o conteúdo do arquivo local ignorado pelo Git `scratch/hunter_maintenance_token.txt`. Não enviar o token por mensagem nem colocá-lo na URL. Configurar `HUNTER_MAINTENANCE_BACKUP_DIR` para uma pasta absoluta **preexistente e fora da árvore do projeto/servidor web**, com acesso restrito à conta do processo. Disponibilizar `pg_dump` e `pg_restore` no PATH ou definir `HUNTER_MAINTENANCE_PG_DUMP` e `HUNTER_MAINTENANCE_PG_RESTORE` para os executáveis do PostgreSQL. Se o TLS termina no proxy confiável, configurar `DJANGO_USE_X_FORWARDED_PROTO=true` e conferir que `request.is_secure()` identifica HTTPS. Manter `HUNTER_CREATOR_RULESET_CHECKSUM=da099956cb1abed5d158f64855076825d66e509a5d5aee0e4f19944291ce6289` até a aplicação.

Após o deploy, o agente consulta `GET` e envia `POST` com `Content-Type: application/json`, `Authorization: Bearer <token>` e corpo exato `{"action":"apply","expected_current_checksum":"da099956cb1abed5d158f64855076825d66e509a5d5aee0e4f19944291ce6289"}`. O servidor primeiro cria um dump completo em formato customizado e o verifica com `pg_restore --list`; se isso falhar, não escreve. O SQL usa transação, preflight de identidade/checksum e é idempotente. A resposta expõe apenas código de estado e contagem, nunca o backup, dados pessoais ou traceback. Guardar o dump no servidor para recuperação; a rota não o disponibiliza para download.

Depois de confirmar a instalação, alterar `HUNTER_CREATOR_RULESET_CHECKSUM` para `ed230c319a8959a78cce978a1e72d11281f9f03bbe49b4c3f0e0158eb2a6e0a2`, reiniciar o serviço e repetir o diagnóstico protegido e o QA visual/funcional. O `POST` altera dados versionados no banco; ele não muda variáveis de ambiente nem ativa sozinho o ruleset público. Remover `HUNTER_MAINTENANCE_TOKEN` após o aceite para desativar o acesso.
